## Must fix

1. **The approval diff hides a reordered page.** [diff.ts:12](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/diff.ts:12) compares line counts, rather than order, once a page exceeds 700 lines. I reversed a 701-line page with a read-only Bun check: the bodies differed, but `diffStats` reported zero additions and zero removals, and the diff contained only a “too long to line up” notice. A reviewer cannot see the change they are approving. Use an order-aware diff at this size, or show the complete before and after bodies when alignment is too costly. Test a reorder beyond line 700.

2. **A card can outlive its proposal.** [service.ts:483](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:483) writes a `pending-*` proposal, creates the SQLite card, then writes the card-named proposal. A crash or failed second write leaves an open card that `accept()` rejects with 410. On restart, [restore():563](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:563) deletes the pending proposal instead of reconnecting it to the card. Give proposal and card one durable identity, reconcile both sides on startup, and fault-inject failure after card creation.

3. **Failed agent reports can still be lost.** [service.ts:212](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:212) queues a failed ship or decision source, but [saveQueue():240](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:240) swallows a state-write failure and persists only the last 500 entries. Those updates are excluded from transcript capture at line 340. A restart after a full disk or unwritable state file loses the in-memory reports; a restart with more than 500 queued entries loses the oldest. Replay them from durable session events or persist a cursor-backed queue without silent truncation. Test both failures and restart.

4. **A successful edit can disappear from History.** [service.ts:684](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:684) returns success after swallowing a failed log or index write. A later `finish()` rebuilds the index but never adds the missed edit’s log entry. `addSource()` similarly swallows its log failure at line 198. Keep a durable finalization record and replay missing log entries; test failure after the page rename and verify History after restart.

5. **Transcript capture permanently drops long event text.** [service.ts:297](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:297) cuts each speech, typed prompt, or decision event at 600 characters; line 328 then advances the cursor past the full event. Detail after character 600 can never enter the wiki, contrary to [SPEC.md:1690](/Users/cheyrasmussen/jamsesh-p7/jamsesh/SPEC.md:1690). Chunk long events with durable offsets, and test a decision whose substantive part appears after the cutoff.

6. **Malformed state silently resets ingest history.** [files.ts:525](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/files.ts:525) treats invalid `.wiki-state.json` as fresh state. That discards the queue, source offsets, transcript cursors, and migration marker; the next write can cement the reset. Fail closed and preserve the damaged file for recovery. Test malformed JSON across restart.

7. **The project root bypasses the symlink rule.** [service.ts:152](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:152) resolves the supplied project directory with `realpathSync` without rejecting a symlinked project root or checking that its result remains under the intended projects directory. The later `vaultDir` checks cover child folders, not that root. A linked project can make wiki initialization and writes land elsewhere, despite [SPEC.md:1749](/Users/cheyrasmussen/jamsesh-p7/jamsesh/SPEC.md:1749). Validate the project root and its ancestry against the trusted projects directory before creating files; cover root links in the path tests. The child-folder `lstat` followed by a path-based write also remains vulnerable to a concurrent folder swap.

8. **A proposal is announced as an update before approval.** [service.ts:431](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:431) broadcasts proposed slugs as `kind:"ingest"`. [WikiStage.tsx:17](/Users/cheyrasmussen/jamsesh-p7/jamsesh/web/src/wiki/WikiStage.tsx:17) displays them under “Just updated,” and [http.ts:269](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/http.ts:269) forwards that bus message to agent sockets. No page body reaches `jam_join` or `jam_wiki_*` before approval, but unapproved model-chosen page names do leave the board. Keep proposal notifications on the people-only board; pulse and announce pages only after `apply`. Update the bus contract in SPEC.
