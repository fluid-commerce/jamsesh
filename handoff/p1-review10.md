## Must-fix

1. **The open relay can exceed its memory cap indefinitely.** [relay.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/relay.ts:86) checks the unframed payload size, then adds the larger encoded frame to `held`. Once a stalled upstream reaches the cap, empty messages still pass the check and keep adding six-byte frames. There is no post-open frame-count cap. Check the encoded size before queuing, cap queued frame objects, and close with 1013 at either limit.

2. **Font transfer can silently lose faces.** [fonts.rs](/Users/cheyrasmussen/jamsesh-p1/jamsesh/app/src-tauri/src/fonts.rs:113) drops files over 48 MB and can send only part of a family over 96 MB without reporting it as deferred. [canvasJoin.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/canvasJoin.ts:225) then settles that family; once one face loads, the canvas may stop reporting the family as missing. Return explicit per-family completion status and page through remaining files. Settle only after every file has loaded or the Mac explicitly reports the family unavailable.

3. **A parity directive can close without a parity exchange, or remain stuck after a real one.** [session.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:646) accepts any outgoing message and any incoming message after the directive, even when they involve different agents and unrelated work. It searches only the newest 400 messages. It also excludes inline replies, although `jam_ask` records a prompt answer as inline and the error tells agents `jam_ask` works. Tie the messages to this directive and the same named counterpart, include prompt answers, and query without the arbitrary recent-message cutoff.

4. **Directive completion is not terminal.** [setDirectiveFor](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:655) protects `cancelled` but lets a late `jam_ack acked` change a completed directive back to `acked`. It also accepts acknowledgements from agents outside `targets`, allowing misleading results and “Done” events. Require target membership and make completed progress immutable except for idempotent repeats.

## Design concerns

[Canvas.stop()](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/canvas/canvas.ts:133) still fires off server cleanup and merely signals the key wrapper; [hub shutdown](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/hub.ts:163) does not await that cleanup before process exit. The parent watcher now has a TERM/KILL grace for direct helpers, so the earlier unbounded-wait defect is addressed at code level. Make shutdown await reaping; use process-group cleanup if configurable helpers may spawn descendants.

[Parity recipients](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/brain/brain.ts:934) are still selected by platform without product identity. This remains the documented data-model decision; unrelated apps can receive checks. The [feed](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/ui.tsx:396) also retains and renders every event a window has ever seen, so long sessions need a bounded or virtualized list.

I could not verify the watchdog in a real Mac app or the relay and reconnect path against a real `figcraft-server`. Those are release checks for the Mac recovery claim.

The round 9 changes are present in source: the wrapper has TERM/KILL escalation, the relay uses an accounted upstream client, font responses have multiple entries and a deferred list, and coordinate updates no longer auto-complete directives. The current tests miss the empty-frame relay case, partial font families, `jam_ask` completion, and late acknowledgements. Replace the fake-send relay assertions as evidence of bounded memory with a stalled-peer test covering empty frames. No production abstraction warrants deletion on this review.
