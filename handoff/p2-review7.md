## Must fix before shipping

1. **A removed Claude Code chat can rejoin through a fresh MCP session.** [mcp.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/mcp.ts:415) generates a new `mcp:<sessionId>` when `jam_join` omits `chat`. After removal and an MCP reconnect, `ctx.agentId` is null, so [the removal check](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/mcp.ts:423) matches neither the old chat ID nor the old agent ID. The call registers a new agent without anyone allowing the removed chat back in. Require a stable Claude Code chat ID for `jam_join`, and test removal followed by a fresh MCP session that omits `chat`.

2. **The instruction-file stripper can delete a concurrent user edit.** [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:219) unlinks a regular file when removing the old block leaves it empty. That branch runs before the changed-file check at line 230. If the file initially contains only JamSesh’s block and an editor adds a rule during installation, the installer can delete the edited file. Apply the changed-file check to the empty-result path before unlinking. The concurrent-edit test starts with other text in the file, so it misses this path.

3. **A queued prompt can still cross rooms during a host switch.** [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:143) checks the queued room, then separately posts the prompt at line 148. If the local relay switches hosts between those requests and that chat has joined the new host, [the hook route](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/http.ts:585) accepts the prompt: it never checks the queued room ID. A successful response also deletes the queued copy. Send the expected room ID with every hook POST and reject a mismatch at the hub before recording or acknowledging anything. Test a switch between the joined response and prompt POST.

4. **The removal gate expires after enough removals.** [session.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/session.ts:565) retains only the newest 200 removed-chat records. Removing a 201st chat drops the oldest tombstone, allowing that chat ID to join again. Keep removal records until a person explicitly allows them or the room is deleted; test across a restart.

The Round 6 per-file queue and dev-server generation guard are present. The stripper’s re-read protects nonempty replacements, and the docs describe the new queue. The room-binding and stripper protections remain incomplete in the paths above. Hook routes check agent credentials and matching machines; I found no new cross-machine bypass. Same-Mac impersonation and self-declared person identity remain the documented limits.

Delete [Hub.onListen](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/hub.ts:629) if it is not a supported API: production calls `listen` directly, and only a test calls the wrapper. Add failure tests for the four paths above; the existing room-switch test switches between completed hook calls.
