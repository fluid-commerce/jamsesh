## Must fix before shipping

1. **An unrelated message can satisfy a parity directive.** [session.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:789) gives a plain message the directive ID from the last message between the same two agents, with no reply ID or time boundary. A counterpart can send a linked parity message; much later, the target can send an unrelated plain message to that counterpart. [exchangeGap](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:650) then sees both directions and permits `jam_ack done`. Require an explicit `directiveId` on `jam_message`; keep the ID inherited by `jam_answer` from its ask. Add a test for the unrelated later message.

2. **Shutdown can report helpers reaped without observing their exit.** After SIGKILL, [stopHelper](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/children.ts:34) races `proc.exited` against another timer. [Canvas.stop](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/canvas/canvas.ts:133) treats either result as reaped, and [Hub.shutdown](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/hub.ts:164) can return after six seconds even if stopping is unfinished. Await exit after KILL; if a hard deadline remains, report failure explicitly instead of resolving as reaped. Test the promise’s timing, not only eventual PID disappearance.

3. **The bundled Mac recovery claim still lacks a release check.** The watchdog and hub restart paths were not exercised in a bundled app. Before shipping Phase 1, run the owner’s release check on the bundle: hang a visible page, kill the hub, and confirm window recovery, hub restart, and port release. Code inspection cannot establish that these platform paths work.
