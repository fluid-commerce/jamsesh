## Production findings

1. **Must fix — shipped news can still become agent work.** [brain.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/brain/brain.ts:932) asks the router to send `coordinate` directives after a one-platform shipment, and the system prompt at line 1352 says other platforms’ agents *should* get one for visible work. `pair_agents` creates inbox directives. The new test mocks `consider`, so it cannot catch this routing. Remove the unconditional rule. Require an identified cross-platform task before creating a directive, and test the resulting inboxes.

2. **Must fix — the browser’s Stop Sharing control misses self-started shares.** [rtc.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/rtc.ts:140) closes over a temporary share ID. [renamePublication](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/rtc.ts:145) replaces that ID after registration; the `ended` handler then calls `stopPublishing` with an ID no longer in the map. The capture and live hub share can remain. Read `pub.shareId` when the track ends, and test that sequence.

3. **Must fix — a paired participant can alter another participant’s share.** [http.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/http.ts:576) accepts the caller-supplied `deviceId` when starting a share and any share ID when ending or declining one. The human-only guard excludes agents but does not check which paired browser owns the share. Bind these operations to the authenticated device, with an explicit host path where needed.

4. **Must fix — removing a share from the big screen can leave it capturing for nearly a minute.** [session.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:970) gives every unseen *current* share the 60-second placement window, including one already shown and then removed. `sharesShown` is also populated only during a sweep, so a brief appearance can be missed. Record placement when a stage displays the share; apply the placement window only before that first display and the five-second grace after removal.

5. **Must fix — the one-share and one-prompt rules still fail across windows.** [session.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:872) replaces a live share only when its `deviceId` matches, although `requestShare` promises one per **person** and kind. [share.tsx](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/share.tsx:243) also retains a request when it has disappeared from `state.shares`, which is exactly what happens after it is answered, declined, or expired. End the person’s prior same-kind share, notify its publishing device, and retain prompts only while the request exists with `status === "requested"`.

6. **Must fix — canvas reconnect can remain stuck.** [ui.tsx](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/ui.tsx:975) returns from every poll when `collab.peers` rejects; it never enters the failed state or schedules a rejoin. A promise that does not settle can also accumulate overlapping polls. Give the command a deadline, treat rejection as a failed poll, and allow only one poll at a time.

7. **Must fix — hub canvas recovery has two dead ends.** [canvas.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/canvas/canvas.ts:134) reads server stderr to EOF after a failed health check. A living but unhealthy child keeps the pipe open, so `start()` never reports failure or installs its watchdog. At [line 524](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/canvas/canvas.ts:524), the watchdog skips a dead host canvas process altogether, leaving the canvas marked live. Bound startup diagnostics and stop the failed child; recreate and rejoin a dead host process, or mark the canvas failed.

8. **Must fix — older transcript lines can become unreachable.** [ui.tsx](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/ui.tsx:404) derives the history cursor from filtered feed events. If the current state window contains only non-feed events, `first` is absent; [loadOlder](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/ui.tsx:428) refuses to page and no Earlier button appears, even when older speech exists. Page from the oldest raw state event and allow loading when the visible feed is empty.

## Design and test concerns

- [brain.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/brain/brain.ts:303) spends up to 45 seconds asking a model to perform the deterministic default placement of a new share. Set the single full-screen tile directly; reserve model routing for an explicit room request to show something beside it.
- [session.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:707) reads only the newest `limit * 3` decisions before filtering by workstream. More than 30 unrelated decisions can hide an older relevant one, after which [hub.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/hub.ts:465) advances the seen mark past it. Filter before limiting or page until ten relevant decisions are found.
- [bench.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/test/bench.ts:87) wraps `brain.tools` without forwarding its third `from` argument. Scenario runs therefore exercise the unrestricted person tool set even for agent input. Forward the argument; rerun the scenarios.
- [canvas.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/canvas/canvas.ts:95) creates reap and watchdog intervals that `stop()` never clears. Retain and clear both handles. [watchdog.rs](/Users/cheyrasmussen/jamsesh-p1/jamsesh/app/src-tauri/src/watchdog.rs:65) should also reset a hidden window’s silence clock so revealing a healthy page does not immediately restart it.
- [boot.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/boot.ts:18) can start an offline first visit with no host ID. [identity.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/identity.ts:51) cannot subsequently confirm the real ID, so the [outbox](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/offline.ts:400) remains unable to send until reload. Add a verified first-ID transition.
