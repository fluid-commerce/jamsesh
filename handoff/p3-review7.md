## Must fix before shipping

1. **One “yes” can approve a host build and a screen change.** [brain.ts:124](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/brain/brain.ts:124) decides pending host requests, then checks the same speech batch for show requests. Host decisions neither mark the line used nor count in [openQuestionsFor](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/session.ts:1654). If both questions are pending, a timely “yes” can approve the build and replace the locked screen. Count host requests in the ambiguity check and consume a line when it decides one request. Test the mixed-request case.

2. **The successful presenter path bypasses the stage revision check.** [placeShare](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/brain/brain.ts:328) captures a revision for its fallback, but gives the model [set_layout](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/brain/brain.ts:361), whose [stage write](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/brain/brain.ts:786) has no `ifRev`. A late model response can replace a newer unlocked stage or pin; its tile check also accepts a share that has ended. Apply the captured revision and live-share check to the model tool as well as the fallback. The new [delay tests](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/test/share-delay.test.ts:9) force model failure, so they cannot catch this.

3. **Duplicate screen names silently select the first display.** [configureScreens](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/session.ts:1390) accepts duplicate names, while [screenMatch](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/session.ts:1413) uses `find` for an exact normalized name. Two screens named “Left TV” therefore route a cast to whichever appears first. A disconnected `screen-20` can likewise resolve as another display deliberately named “screen-20.” Reject ambiguous exact names, and reserve ID-shaped references for exact ID lookup. Test both collisions.

4. **A prior failed save can stop a healthy new session and leave its windows dead.** A failed stop persists in `Turns::unsaved`; hosting can subsequently start again. [reopen](/Users/cheyrasmussen/jamsesh-p3/jamsesh/app/src-tauri/src/main.rs:1159) stops that new hub *before* checking `unsaved`, then leaves its windows open when this stop succeeded and reopening is blocked. Check the prior failure before stopping the current hub. The dialog callback also [clears `unsaved` before validating its ticket](/Users/cheyrasmussen/jamsesh-p3/jamsesh/app/src-tauri/src/main.rs:1143); move that clearance into the valid turn so an old dialog cannot clear a later failure.

5. **Screen setup still mutates state outside its transition turn.** [screens_save](/Users/cheyrasmussen/jamsesh-p3/jamsesh/app/src-tauri/src/screens.rs:674) writes the setup before `arrange_for` checks its ticket. [toggle_userless](/Users/cheyrasmussen/jamsesh-p3/jamsesh/app/src-tauri/src/main.rs:1061) and the [menu path](/Users/cheyrasmussen/jamsesh-p3/jamsesh/app/src-tauri/src/main.rs:869) change config and [open or close the client window](/Users/cheyrasmussen/jamsesh-p3/jamsesh/app/src-tauri/src/main.rs:1041) outside the turn too. A concurrent switch can reject the eventual arrangement after those changes have already affected the next session. Acquire a quiet turn before reading, saving, or changing windows, and keep it through arrangement.
