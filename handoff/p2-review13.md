## Must-fix

1. **A late HTTP fallback can erase a newer socket update.** [hub.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/web/src/shared/hub.ts:285) advances its sequence for socket `state` messages, but not for `patch` or `event` messages. I reproduced this: start `refreshState()`, apply an `agents` patch, then resolve the older HTTP response. The final state contains the old agents. A directive or other room change can disappear until another update arrives. Invalidate or replay an in-flight fallback when an incremental socket message changes state, and test that order.

2. **Two setup runs can undo each other.** [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:306) backs up and restores shared files and the single Claude MCP entry without a lock. [“Connect my agents”](/Users/cheyrasmussen/jamsesh-p2/jamsesh/app/src-tauri/src/main.rs:760) can launch overlapping runs. If run B succeeds while run A later fails, A can restore the old credentials and remove B’s MCP entry, although B reported success. Hold an exclusive per-home install lock from backup through commit or rollback; test two interleaved runs.

3. **Rollback can expose an earlier secret in the process list.** [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:432) moves only an inline `Authorization` header to a file. Other credential headers, or secret `env` values in the saved entry, remain in `rollback_mcp`, which is passed as an `add-json` argument at line 346. Move every credential-bearing value out of arguments where supported; otherwise refuse the reinstall before removing the earlier entry.
