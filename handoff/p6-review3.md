## Must-fix before shipping

1. **A stale Stop can end the next recording.** [hub.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/hub.ts:497) identifies a recording by device at the time Stop *arrives*. If recording B starts before a delayed Stop for A arrives, that Stop captures B, closes B’s prompt window, and eventually ends B. Stop also accepts no active recording and can issue a recording ID from typed text. [annotate.tsx](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/annotate.tsx:824) makes this more likely on a person’s own screen by starting asynchronously and ignoring failure. Return A’s ID from Start, require it on Stop, bind the time window to the server’s recording, and await Start before showing Record as live. The new test covers B starting *during* Stop’s wait, not before Stop arrives.

2. **A Mac mouse button can remain down after control changes or a connection drops.** [liveapp.tsx](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/liveapp.tsx:108) sends separate down and up requests. Cancellation and capture loss now send up, but [DriveLayer.tsx](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/host/DriveLayer.tsx:81) discards a departing driver’s replay state without one; tile unmount has the same gap. After control passes, [liveapps.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/liveapps.ts:491) can reject the old driver’s up. The [Swift helper](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/native/jamsesh-live.swift:196) has no pressed-button watchdog. Track presses at the hub or helper and force an up on control loss, disconnect, tile removal, and timeout. Test those paths and a lost up request.

3. **Build input can likewise retain a held button or key.** [DriveSurface.tsx](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/DriveSurface.tsx:107) sends `leave` on blur or pointer-lock loss, then no longer forwards a later keyup. [devdrive.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/devdrive.ts:45) handles `leave` as mouseout only; its `btns` and `downEl` remain set. A build that tracks keydown or pointerdown can stay in that state. Track forwarded presses and emit terminal releases on leave and driver removal; make the injected script clear its own pressed state as a backstop.

4. **The open-font room cap still races.** [fonts.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/fonts.ts:355) computes the remaining allowance, then awaits the entire read. It increments `reserved` only *after* that await. Concurrent downloads can each read against the same allowance and all commit, exceeding 96 MB. Reserve capacity before reading, or enforce the aggregate limit at commit. The [concurrent test](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/test/fonts.test.ts:581) uses ordinary fast responses and does not force reads to overlap.

5. **Reconnect still fails for a build that has not yet been driven.** [drivetiles.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/drivetiles.ts:21) returns immediately when no key has been fetched. A frame can load, the hub can restart, and the reconnect handler in [ui.tsx](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/ui.tsx:273) will not reload that frame. The first later driving event fetches the new key, which the frame’s old injected script rejects. Refresh or invalidate every proxied frame on reconnect, including when the key was never cached. Add that exact case to the frame-driver test; its current restart case primes the key first.

6. **Native capture and CGEvent input still need real-host verification before this phase ships as complete.** [STATUS.md](/Users/cheyrasmussen/jamsesh-p6/jamsesh/STATUS.md:41) marks ScreenCaptureKit capture simulated and [Mac/Electron capture and input](/Users/cheyrasmussen/jamsesh-p6/jamsesh/STATUS.md:45) untested. The reported Rust clippy run, 42 passing Rust tests, and Swift typecheck establish compilation and test results, not permission or event behavior. Complete the existing office checklist on a host with the required permissions before release.

## Design concerns and smaller fixes

- **Should-fix:** [fonts.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/fonts.ts:512) now limits each caller to eight lend tickets, but tickets need not name a wanted family. Thirteen callers can fill the global pool of 100 and block a legitimate lender for up to two minutes. Require a wanted family and reserve capacity for other callers or evict the oldest ticket globally.
- **Should-fix:** Delete the duplicated Mac press lifecycle in the local handlers in [liveapp.tsx](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/liveapp.tsx:108) and the replay tracker in [tileinput.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/tileinput.ts:24) once the hub or helper owns release. Component-local ordering remains useful for smooth drags, but it cannot guarantee release after control changes or network failure.

The other Round 2 findings are addressed at their cited paths: legacy prompt routes check device ownership; a Stop already waiting ends only its captured recording; Start validates before replacing; pointer cancellation sends up and Mac requests are serialized; frame keys refresh when one is cached. Helper pause/resume, per-caller ticket limits, scoped Record control, and the trail wording are also present. The font-cap and reconnect fixes have the gaps above.
