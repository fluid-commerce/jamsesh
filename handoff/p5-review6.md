## Production blockers

1. **Two room speakers can become one line before deduplication runs.** [pipeline.ts](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/audio/pipeline.ts:187) groups overlapping segments by time. [splitCrosstalk](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/audio/pipeline.ts:249) separates them only when their spans are shifted by at least a second; [emit](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/audio/pipeline.ts:281) transcribes one best segment. Two people speaking different words at nearly the same time on different room laptops can therefore lose one utterance. The exact-word and voice checks in `mergeTwin` never see it. This contradicts the “when unsure, both lines are kept” claim in [SPEC.md](/Users/cheyrasmussen/jamsesh-p5/jamsesh/SPEC.md:1201). **Fix:** require evidence that segments contain the same utterance before combining them, or transcribe and retain ambiguous copies separately. Add a simultaneous, same-span, different-words room test.

2. **Hybrid echo removal can discard extra spoken words.** [pipeline.ts](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/audio/pipeline.ts:397) drops a line across room and remote locations when `textSimilarity` reaches 0.55. That helper compares sets of words and divides by the *smaller* set ([line 668](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/audio/pipeline.ts:668)): “Yes” and “Yes please” score 1. A real response can be dropped as an echo. The existing hybrid test checks distinctly worded speakers, not this case. **Fix:** make echo removal preserve lines with added or changed words; test a short reply and an overlapping echo separately.

3. **A paired browser can teach or damage another person’s voice without their approval.** The correction route deliberately exempts its target `personId` from caller binding ([http.ts](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/http.ts:42), [line 426](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/http.ts:426)). Any paired human window can POST `/utterances/:id/assign` naming another person ([line 548](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/http.ts:548)); `assign` adds that line’s embedding to the target and can remove samples from the previous label ([pipeline.ts](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/audio/pipeline.ts:568)). The read and Reset ownership checks do not cover this write path. **Fix:** keep collaborative transcript correction, but require the target person’s or host window’s approval before a correction changes voice samples. Test a correction submitted by a different paired browser.

4. **Reset can be undone by audio captured before it.** [resetVoice](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/hub.ts:393) does not cancel a read already in progress; [enrol](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/audio/pipeline.ts:639) dates its samples at upload, so a recording begun before Reset and uploaded after it teaches the voice again. Buffered audio also uses `min(arrival, supplied t0)` as `heardAt` ([pipeline.ts](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/audio/pipeline.ts:177)); a device timestamp ahead of the host can put pre-Reset audio past the Reset gate. Removing voice travel does not make either path moot: both learn on this host. **Fix:** invalidate in-progress reads and pre-Reset queued audio for voice learning with a host-issued reset generation, while allowing a new read begun after Reset. Test both races.

5. **Malformed WAVs still escape the promised 400 response.** [decodeWav](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/audio/wav.ts:22) reads `fmt ` fields without checking that the chunk contains 16 bytes, and accepts `data` before any `fmt ` chunk using default format values. A truncated `fmt ` produces `RangeError`; the upload and read routes map only `BadWav` to 400 ([http.ts](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/http.ts:487)), so this becomes a logged 500. The new tests mutate valid headers but do not exercise truncated chunks. **Fix:** validate `WAVE`, chunk bounds, `fmt ` size and presence, and complete sample frames before reading; throw `BadWav` for each malformed case.

6. **The Mac copy migration can leave voice data behind silently.** Startup ignores failure to delete [voiceprint.json](/Users/cheyrasmussen/jamsesh-p5/jamsesh/app/src-tauri/src/main.rs:968). The previous store also wrote `voiceprint.json.<pid>.<counter>.part` before rename ([historical voiceprints.rs](/Users/cheyrasmussen/jamsesh-p5/jamsesh/app/src-tauri/src/main.rs:968)); a process killed during that write can leave such a copy, which startup never removes. **Fix:** remove the known temporary-file pattern as well as the final file, and surface or retry deletion failures. Test migration from a final copy, an interrupted temporary copy, and a deletion failure.

7. **Model path checks still have avoidable destructive and integrity gaps.** [whisper.ts](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/audio/whisper.ts:131) deletes any rejected model under the managed models directory, including an explicitly chosen `JAMSESH_WHISPER_MODEL` in a subdirectory; the sibling-prefix fix works, but it does not restrict deletion to JamSesh’s exact managed filename. [parakeet.ts](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/audio/parakeet.ts:96) verifies the manifest only when the chosen path string equals `own`; an environment path such as `models/./parakeet-tdt-0.6b-v2-int8` names the same managed directory but skips verification. **Fix:** compare canonical paths, delete only JamSesh’s exact managed Whisper file, and never delete an explicitly chosen path. Verify the Parakeet manifest whenever the resolved path is the managed model.

## Design concerns and cleanup

`mergeTwin` finds the nearest text match before checking voice ([pipeline.ts](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/src/audio/pipeline.ts:377)). If that candidate’s voice disagrees, it never tries a second eligible match. This can leave a duplicate; filter by voice before choosing the nearest candidate.

The removed host-to-host voice transport and acoustic matching have no active routes, commands, settings, or source paths in the searched hub, web, and Mac app trees. The `carried`-row migration runs when each `Store` opens, including the team store. Cleanup remains in the stale “voiceprints that travel” test heading ([voices.test.ts](/Users/cheyrasmussen/jamsesh-p5/jamsesh/hub/test/voices.test.ts:266)) and the obsolete “ask to share” People description ([SPEC.md](/Users/cheyrasmussen/jamsesh-p5/jamsesh/SPEC.md:1656)). The web test titled “nothing about a voice is kept on the device” checks only module export names ([voiceprint.test.ts](/Users/cheyrasmussen/jamsesh-p5/jamsesh/web/test/voiceprint.test.ts:42)); delete that assertion or replace it with a migration/storage behavior test.
