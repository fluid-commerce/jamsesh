## Must fix

1. **The Mac helper can exit with a mouse button down.** [jamsesh-live.swift](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/native/jamsesh-live.swift:215) posts a tap’s down event, sleeps, then posts up without tracking the press as `held`. The `down` path also posts before setting `held`, and `up` clears it before posting the release. Capture failure or SIGTERM can call `quit()` from another thread in those gaps; `releaseHeld()` then has nothing to release. Serialize button events, held state, and quit on one queue, including taps. Exercise interruption during each transition on a permission-enabled host.

2. **A rapid new recording can put its speech in the previous recording’s notes.** [hub.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/hub.ts:527) allows utterances starting up to 300 ms after A’s Stop time while A waits for transcription. If B starts on the same device during that interval, B’s utterance can enter A’s notes and later B’s. Bound A’s speech window at B’s Start time, then test a restart within 100 ms while A’s Stop is still waiting.

3. **A sent recording can be sent again after receipt eviction.** [hub.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/hub.ts:589) caps ownership entries and send receipts independently at 200, in different orders. Stop A1–A200; send A200, then A1–A199; stop and send A201. A200 still has an ownership entry but its send receipt has been evicted. Retrying A200 creates another directive or brain event, contrary to the at-most-once contract in [SPEC.md](/Users/cheyrasmussen/jamsesh-p6/jamsesh/SPEC.md:1525). Keep ownership and send status in one ledger, or retain a sent tombstone; after eviction, refuse a retry rather than sending again. Test this out-of-order sequence.

4. **The legacy start route can replace a modern recording’s prompt window.** [http.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/http.ts:895) calls `promptStart` for an authorized device even when that device has an active recording. [hub.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/hub.ts:255) releases the recording’s window and installs an ID-less legacy one; the later Stop no longer closes its own window. Return 409 without changing state when a recording is active, and test the window and speech after refusal.

5. **The native release check remains open.** [STATUS.md](/Users/cheyrasmussen/jamsesh-p6/jamsesh/STATUS.md:47) requires actual ScreenCaptureKit capture and CGEvent input checks before release. Swift typechecking, Rust tests, and fake-helper tests do not establish that capture, input, and interrupted button release work with macOS permissions. Run and record the office checklist on a permission-enabled host before shipping.
