## Production blockers

1. **Paired windows can take over another person’s device or share.** [http.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/http.ts:420) accepts any `deviceId` without the Phase 1 pairing owner check. The share routes at [line 619](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/http.ts:619) likewise let a paired window start, end, or decline a share by supplying another device or share ID. The diff removes the prior `pairedId`, own-share, and requested-person guards. Restore those checks and tests for a foreign window.

2. **A machine credential does not identify a chat.** [hub.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/hub.ts:436) selects an agent using a caller-supplied `session_id` plus the machine. All chats on that machine share the agent credential, so one can submit another chat’s ID to read or acknowledge its room items, or post a prompt as its person. The cross-Mac test does not test this boundary. Bind hook calls to a chat-specific capability, or state and enforce a machine-level trust boundary instead of claiming chat isolation. The related [joined route](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/hub.ts:448) also clears a removal from an unverified `connect: true` claim; the [hook script](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:63) can make that claim from a prompt such as “don’t connect to jamsesh.” Require an authenticated person action to allow rejoining.

3. **Remove does not stop an already waiting listener or dispose of its tasks.** [session.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/session.ts:525) deletes the agent but leaves its directives and listener. After `await session.wait`, [hub.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/hub.ts:619) can use the captured agent to offer a pending item and wake a removed chat. Those directives also lose their tile and are skipped by aging. Cancel the listener and its deliveries on removal, revalidate membership before returning from `listen`, and cancel or offer each outstanding target for reassignment.

4. **Queued prompts can be lost or repeated.** [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:112) clears the whole outbox even when replay of a prompt fails. If the original request succeeded but its response was lost, replay posts the same prompt again. Give queued prompts stable IDs, deduplicate them on the hub, and remove each entry only after an acknowledged replay; protect concurrent outbox writes.

5. **Canvas startup can hang indefinitely, and a dead host no longer recovers.** [canvas.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/canvas/canvas.ts:134) reads child stderr to EOF after the health timeout; a child that remains running holds that pipe open. The diff removed the bounded read and child shutdown. Its [watchdog](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/canvas/canvas.ts:523) now returns when the host process dies, where Phase 1 restarted it. Restore bounded failure handling and host recovery, with tests for a live but unhealthy child and a dead host.

6. **Screen sharing can remain live after the browser’s Stop sharing action.** [rtc.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/web/src/shared/rtc.ts:140) registers a track-ended callback with the provisional share ID. [renamePublication](/Users/cheyrasmussen/jamsesh-p2/jamsesh/web/src/shared/rtc.ts:146) changes the map key; the callback then stops the old ID and misses the live publication. Use `pub.shareId` in the callback and test stop after rekeying. The share request queue at [share.tsx:243](/Users/cheyrasmussen/jamsesh-p2/jamsesh/web/src/shared/share.tsx:243) also retains a request absent from state indefinitely; remove it when the request expires or disappears.

7. **A large purge remains visible in an open feed.** [hub.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/web/src/shared/hub.ts:313) keeps only 500 removed event IDs, while [RoomFeed](/Users/cheyrasmussen/jamsesh-p2/jamsesh/web/src/shared/ui.tsx:393) retains all previously seen events. Purging more than 500 posts leaves the earlier ones on screen. Clear the feed cache from the full removal event or rebuild it from authoritative history.
