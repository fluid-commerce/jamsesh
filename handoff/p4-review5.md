## Must-fix

1. **An explanatory file request can still enable actions.** [brain.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brain/brain.ts:1567) applies clause checks to broad keyword patterns. A read-only probe returned `true` for `cancel_directive` on “Explain why we should cancel the old task in this file,” `record_decision` on “Summarize why we decided on option B in this PDF,” and `pair_agents` on “Explain how to pair agents from this plan.” The execution check at line 1088 repeats the same predicate. Attached text can therefore steer a model into using an offered action tool. Require an affirmative instruction for **each** mutating tool, and test these explanatory forms with adversarial file content.

2. **Overlapping sessions can erase accepted context without changing it.** [carryover.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:69) counts any recent event as `activeAt`; [the commit check](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:225) then replaces the entire project snapshot. If session B accepts a fact, then older session A merely receives a later utterance and saves, A’s snapshot wins and B’s fact disappears from the next session. Merge divergent accepted changes or resolve the conflict explicitly; room activity alone cannot authorize replacing the accepted set.

3. **Stale-lock recovery still permits two live writers.** In [acquireLock](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:177), two takers can judge the same dead lock stale. After one installs a live lock, the other can move it aside; a third taker can acquire the vacant path before `linkSync` restores it. Restoration then fails, and line 189 deletes the live owner’s lock. The token check immediately before rename does not close the gap between that check and rename. Use a per-project lock whose ownership cannot be transferred by pathname replacement, such as a shared SQLite write transaction, and test competing stale-lock takers with a paused writer.

4. **A genuine veto can vanish from a waiting card.** [Board.repeat](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/board.ts:120) clears `overruled` for *any* new matching source. [Board.overrule](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/board.ts:445) stores the veto only in that field, so a third person repeating the rejected ask removes the only visible record of the room’s rejection. Keep the veto and its source in card history; require an explicit renewed decision to clear it or create a new proposal.

5. **Carry-over silently drops accepted items at its size limits.** [snapshotContext](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:82) takes only the newest 300 active facts and first 40 unfinished workstreams. A save with 301 facts succeeds, but the omitted fact cannot seed the next session, contrary to [SPEC §12.7](/Users/cheyrasmussen/jamsesh-p4/jamsesh/SPEC.md:1753). Preserve the full set in validated chunks, or fail the save visibly on overflow until there is an explicit retention rule.

6. **A valid agent token fails on direct loopback attachment fetches.** [http.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/http.ts:193) sets `device` to `null` for every local request, and [GET/HEAD](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/http.ts:575) then returns 401 without a host-window cookie. The relay path works; a paired agent calling the hub directly at `127.0.0.1` does not, despite the documented “any paired device or agent credential” contract. Check the supplied token for this read route even on loopback. Keep the host-window requirement for local requests without a valid credential.

## Design and verification

The six must-fixes in the fourth review are addressed on their intended paths: the `create_directive` file gate, scoped curation pairing and Replace, live-PID lock protection, failed-save reporting, aggregate attachment limits, and unpaired loopback GET/HEAD rejection. Its two should-fixes are also present: unreadable files retain file-pass restrictions, and curation requires a hold. The lock guarantee remains incomplete under competing takeover; the overruled-card change introduces the veto loss above.

Delete the production-unused Boolean [writeProjectContext and commitContext wrappers](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:115). They collapse “skipped” and “failed,” while production now uses the more useful outcome API.

The tests exercise the stated fixes, but [the file-gate test](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/test/p4-round4.test.ts:58) checks only `create_directive`; [the attachment tests](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/test/p4-round4.test.ts:229) force paired traffic through a relay header; and [the lock test](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/test/p4-round4.test.ts:112) simulates a live PID without competing takeover. Add failure-mode tests for the cases above. I ran the read-only intent probe, but not the suites because they write temporary files in this read-only workspace. I could not independently verify the live-gateway, compiled-app, or two-process pause claims.
