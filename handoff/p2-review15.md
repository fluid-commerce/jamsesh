## Must-fix

1. **Setup can write an instruction file through a symlink.** [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:460) downloads the Claude skill directly to its destination; [line 463](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:463) redirects into the command file; [lines 614–617](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:614) write the Codex skill and prompt directly. These operations follow an existing symlink. If one points to `CLAUDE.md` or `AGENTS.md`, a successful setup overwrites that instruction file, despite the explicit prohibition. The transaction also records resolved targets while `private()` and the hook replacement rename over link paths, so a failed setup can leave a replaced symlink behind ([lines 291, 319–327, 404](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:291)). Resolve and validate every destination before writing, preserve its link, and reject an instruction-file target. Test successful and failed installs with symlinked destinations.

2. **An early failure can erase another process’s edit to a file setup never touched.** Setup snapshots all tracked paths before the first change, then restores or deletes *all* of them on failure ([install-scripts.ts:315](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:315), [install-scripts.ts:342](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:342)). For example, if an editor changes `~/.codex/config.toml` during a slow hook download and that download fails, rollback replaces the editor’s work with the pre-run copy. The setup lock excludes another setup, not an editor. Track which paths were actually changed and restore only those; detect a later external change before replacing or deleting one.

3. **MCP rollback can discard unrelated Claude configuration changes.** The restore reads all of `~/.claude.json`, changes one key in memory, and renames a complete replacement file ([install-scripts.ts:359](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:359)). A concurrent Claude Code or user edit between that read and rename disappears. Keep the saved copy and report a conflict when the file has changed during restore; do not report restoration as successful after overwriting a concurrent edit.

4. **The MCP read-back does not prove the user-scope entry was restored.** Removal and installation specify `-s user`, but both checks call unscoped `claude mcp get jamsesh` and use only its exit status ([install-scripts.ts:355](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:355), [install-scripts.ts:359](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:359)). That establishes that an entry named `jamsesh` is visible, not that the saved user-scope entry is back; another scoped entry can make the check pass. Verify the user-scope config key against the saved entry and test with a same-name project entry.
