## Production findings

1. **Must fix — a closed display can keep a share capturing indefinitely.** [session.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:953) counts shares in every saved `screenStages` entry as visible. [removeScreen](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:1063) removes the display from `bigScreens` but leaves its saved stage; a display that stops reporting also disappears from `screens()` without changing that stage. A share shown only there is therefore skipped by every sweep. Count only active displays, and sweep when a display closes or expires. Test both paths.

2. **Must fix — ordinary stage activity can postpone share cleanup without bound.** [scheduleShareSweep](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:964) cancels and restarts the sole sweep timer on every `setStage`. Changes less than five seconds apart can keep an off-screen share alive indefinitely. Schedule against each share’s fixed deadline, or use a periodic sweep that stage changes cannot postpone.

3. **Must fix — disabling the brain disables share placement.** [placeShare](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/brain/brain.ts:304) returns before its full-screen fallback when `brainEnabled` is false. The [share endpoint](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/http.ts:586) still starts capture; nothing places it, and the placement timeout later stops it. Place the share deterministically from the hub regardless of the brain setting. Test sharing with the brain off.

4. **Must fix — shipped news still becomes inbox work by default.** [shippedBatch](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/brain/brain.ts:916) tells the model to call `coordinate_parity` for a user-visible shipment whenever another platform’s agent is online; that tool creates `coordinate` directives that can ask the other agent to build. It does not establish that the other app has a gap. This recreates the earlier failure for, for example, a desktop header change. The [approved plan](/Users/cheyrasmussen/jamsesh/jamsesh-improvement-plan.md) calls for tasks only when another agent has to act. Make shipment news the default and require an identified cross-platform need before issuing a directive. Test actual inboxes; the current visible-shipment test mocks `consider`.

5. **Must fix — failed canvas revival remains reported as live.** [canvas.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/canvas/canvas.ts:519) can throw while restarting the server or rejoining the host. The [watchdog interval](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/canvas/canvas.ts:101) discards that error, leaving the previous `"live"` status and link in place while clients repeatedly reconnect. A failed `waitLive` likewise sets only a reason. Serialize recovery, mark the canvas failed when revival fails, and test a failed restart.

6. **Must fix — a share ID can be reused for the wrong capture kind.** [startShare](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:875) accepts the same device’s existing ID without checking `kind`. Posting a camera with a live screen’s ID rewrites the screen record as a camera without ending its publication. Require a matching kind and an allowed status; otherwise allocate a new ID or reject the request. Test this over HTTP.

## Design and remaining review concerns

- **Should fix:** [endShare](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:925) restores the previous stage only on `main`; ending a share that took over an extra display sends that display to the board. Save and restore the prior stage per display.
- **Should fix:** [roomDecisions](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:702) now filters while paging, but stops after 20 pages. If those 2,000 decisions are irrelevant, [hub.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/hub.ts:463) can advance the seen mark past an older relevant decision. Filter in storage or continue paging without advancing past unread records.
- **Should fix:** The default share placement still waits up to 45 seconds for a model before using a one-tile fallback. Delete that model step for default placement; keep model layout decisions for explicit room requests.
