## Must-fix

1. **An unassigned browser can act as any person.** In [http.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/http.ts:426), the human-only guard blocks agent credentials but does not require a paired browser to have a `personId`. The `/say` check at line 523 only compares identities *if one is already bound*; `actor()` at line 577 then accepts `body.personId` for card actions. A paired browser with no person can name Chey in the body, speak as Chey, or send and dismiss her cards. Require a bound person for these routes and derive the actor from the credential. Keep the host-window identity rule explicit.

2. **Attached text can still reach action tools during a reading request.** [brain.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brain/brain.ts:1464) treats “read,” “look,” and “summarize” as authorization for `create_directive`; “task” offers `triage_card`. I confirmed that “Read this attached brief and tell me its goal” offers `create_directive`, and “Summarize the tasks in this PDF” offers both tools. The file is in a separate message, but tool execution has no check that the person requested the particular action. Use a read-only tool set for file questions; authorize action tools against an explicit action in the person’s words and check that intent at execution.

3. **Overheard questions enter the supposedly accepted brief.** [brain.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brain/brain.ts:222) sets `data.direct` on a sufficiently confident question even when it was overheard. `acceptedEvent` at line 1712 treats every person event with that flag as accepted, and `digest` at line 1285 feeds it to the goal and glossary model. The question is still routed as overheard, so this crosses the approval boundary without a card action. Separate “answer this question aloud” from “the person addressed JamSesh.”

4. **Scope changes are silently deduplicated.** [board.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/board.ts:165) drops a context proposal when `restates` matches an active fact, without checking its workstream or platform. [curation.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brain/curation.ts:157) similarly merges a new item without checking scope. The committed predicate returns `restates: true` for “Header uses option A on desktop” versus “Header uses option A on mobile.” Preserve both scoped facts or put uncertain matches on a card; include scope in both deduplication paths.

5. **A retirement proposal needs no cited event.** [curation.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brain/curation.ts:126) accepts `resolve` and `supersede` entries with missing `eventIds`. [board.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/board.ts:190) then makes a Retire card with a null event source and the model’s reason as its fallback. A person can retire an accepted fact without seeing what in the room supports it. Reject uncited retirement proposals, as the update path already does.

6. **Retiring the last carried fact can resurrect it next session.** [carryover.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:69) excludes all `carriedFrom` items from `lastActive`, even after this session changes their status. If the carried fact is the only settled material, `writeProjectContext` at line 109 also refuses the now-empty snapshot. The old file remains and seeds that fact again. Count local changes to carried items as activity and persist an intentionally empty settled state after an approved retirement.

7. **Reopening a session can import another session’s facts into it.** [carryover.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:130) skips seeding only when the `carried` setting exists or the context file names this session. It does not check whether the resumed session already has its own facts. If session B writes the project file and earlier session A is reopened, B’s facts are inserted into A, including potentially conflicting ones. Do not seed a session that already has its own settled context.

8. **The unreadable-PDF wording guard is bypassed by Merge.** [board.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/board.ts:366) requires only that `text` be supplied for a `needsWording` card. The merge UI [prepopulates that text](/Users/cheyrasmussen/jamsesh-p4/jamsesh/web/src/shared/Tasks.tsx:435) with the file-name placeholder. Clicking Merge can therefore save “sketch.pdf (no text to read: write what to keep)” as knowledge. Apply the same substantive-wording check used by Add and Replace, including to merged text.

9. **A curation pass with no output loses its batch.** [brain.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brain/brain.ts:1297) ignores a null result from `curate` and still advances both digest cursors to `lastId`. [curation.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brain/curation.ts:97) can return null when the model produces no output. Those events are then excluded from the next pass, contrary to SPEC 7.3’s retry promise. Advance the curation cursor only after a completed curation result.

## Should-fix and design

- [board.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/board.ts:302) checks only that a task card has target IDs when Send is clicked. An agent removed or changed to observer while the card waited can leave a sent directive with no valid worker. Revalidate targets at Send and keep the card open if none remain.
- Delete the bespoke PDF text parser in [attachments.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/attachments.ts:199) once a maintained fallback is available. Its regex collects parenthesized strings inside `BT`/`ET` without tying them to text-drawing operators, so it can present nondrawn PDF strings as document wording. The synchronous inflate fallback also runs in the hub process.
