## Must fix before shipping

1. **Vault edits can be missed permanently.** [service.ts:553](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:553) skips a page when its floored modification time matches `seen`, without comparing the hash. An editor that preserves the timestamp, or a second write within that timestamp’s resolution, changes the page without producing an edit source, log entry, or index rebuild. The existing test changes the timestamp and cannot catch this. Compare revisions even when the timestamp matches; carry the revision out of `listPages` to avoid reading every file twice.

2. **A failed state write duplicates edits and can misattribute app edits.** [service.ts:564](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:564) writes a new, unkeyed edit source before saving `seen` at line 575. If that save fails or the process stops between them, the next scan writes a second source for the same revision. Separately, `markSeen` swallows a state write failure at [line 531](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:531); an app edit can succeed and later be filed again as “Someone in the vault.” Give each observed page revision a deterministic source ID, and make failed `markSeen` writes recoverable before reporting an app edit complete. Fault-inject both gaps.

3. **Deleting a page by hand leaves the vault index wrong.** [service.ts:574](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:574) forgets removed pages, but only rebuilds `index.md` when `touched` contains a created or changed page. An Obsidian deletion therefore leaves an index link to a page that no longer exists. It also produces no edit source despite the project’s “edits logged as sources” rule. Record a deletion source and rebuild and commit the index. Test deletion alone.

4. **Shutdown can still capture too early.** The request gate at [http.ts:122](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/http.ts:122) runs only when a request begins. A request already waiting for its body at [http.ts:415](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/http.ts:415) can subsequently call `typed()`. More directly, [Transcriber.stop()](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/audio/transcribe.ts:108) only kills the local process: an in-flight transcription resumes at [pipeline.ts:270](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/audio/pipeline.ts:270) and emits a room event after [captureFinal()](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/hub.ts:239). The shutdown test starts its POST *after* closing and does not exercise either case. Quiesce or await in-flight producers, recheck `closing` after awaited request bodies, and capture again after they drain. Test a transcription and a request held across shutdown.

5. **Out-of-range state is checked after durable work has begun.** [tick() at service.ts:511](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:511) checks cursor ranges, then drains queued sources, files agent reports, scans the vault, and captures transcript before [ingestNow() at line 619](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:619) checks a source read offset. A corrupt offset can therefore be discovered only after sources and cursors have been written, contrary to the stated fail-closed behavior. Validate all existing read and partial offsets against their targets before any tick mutation. Add a test with a corrupt offset and enough new events to force transcript capture.
