## Must-fix

1. **The watchdog calls AppKit off the main thread.** [watchdog.rs](/Users/cheyrasmussen/jamsesh-p1/jamsesh/app/src-tauri/src/watchdog.rs:125) sends `occlusionState` to an `NSWindow` from `tick`, which [main.rs](/Users/cheyrasmussen/jamsesh-p1/jamsesh/app/src-tauri/src/main.rs:971) runs in an async task. The pinned `objc2-app-kit` dependency marks `NSWindow` as main-thread-only; the raw `msg_send!` bypasses that guard. This can crash the Mac app while it is trying to recover a page. Read occlusion on Tauri’s main thread and pass the result back to the watchdog. Test that path in a running Mac app.

2. **Concurrent capture starts can orphan a live camera or screen stream.** [rtc.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/rtc.ts:133) checks `pubs` before awaiting the browser picker. Two calls for the same request can both pass the check; the second `pubs.set` replaces the first publication without stopping its tracks. Stop then releases only the stream still in the map. Make capture single-flight per kind and share ID before calling `getUserMedia` or `getDisplayMedia`. Test two overlapping picker promises and verify that Stop releases every track.

3. **The socket ownership fix has a registration race.** [http.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/http.ts:63) accepts any valid, *unregistered* device ID as the socket’s identity. If another paired window opens that socket before the device registers, it retains the ID after registration and can send RTC messages as that device at line 292. The normal registered-device spoof test does not cover this order. Recheck ownership against the authenticated caller when handling device messages and closing the socket, or bind the socket only after registration. Add a socket-before-registration test.

4. **Stopping the hub during canvas startup can leave helpers running.** [canvas.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/canvas/canvas.ts:100) awaits `startServer()` and `startHost()` without checking `stopped` between them. `stop()` can run while `choosePort()` is pending, before a process exists to kill; startup can then spawn the server and host, announce a live canvas, and return at line 106 without cleaning either up. Check cancellation after each await and clean up any process created after Stop. Test Stop while each startup step is pending.

5. **The key helper can stall canvas startup indefinitely.** [canvas.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/canvas/canvas.ts:184) waits for all of `figcraft-server key` stdout, with no deadline, no child reap, and an undrained stderr pipe. A hung helper never reaches the initial-start failure handler or its retries. Give the command a timeout, drain or discard stderr, and kill and reap it on timeout or error.

Update those rules and delete the unused presenter setting from the product configuration.

## Confirmation and limits

The six findings in review 6 have fixes in this commit for the paths previously identified: registered sockets are owner-checked; initial canvas failures clean up and retry; running server stderr is drained into a bounded buffer; parity calls reject mixed features; extra-display deadlines are restored; and a live canvas poll cancels its rejoin timer. The socket race above remains outside the registered-device test.

`shippedBatch` does not restore general task routing: its tools are limited to `coordinate_parity` and `no_action`, and parity requires the shipping agent’s `seen` text. I ran 17 focused web tests; all passed. I did not run the 37 gateway scenarios or a live Tauri/WebRTC session, so I cannot confirm the reported scenario runs or native recovery behavior. No repository files were changed.
