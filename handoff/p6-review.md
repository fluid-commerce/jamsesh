## Production findings

1. **Must-fix — local processes can read live app frames and borrowed fonts.** [http.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/http.ts:186) treats loopback as authorized but sets `device` to `null`. The new [app WebSocket](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/http.ts:210) and [font download](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/http.ts:497) routes reject only `device?.kind === "agent"`. A local agent or any other local process can therefore read a live Mac window stream and every held font; app IDs and font keys are in room state. Require a paired browser identity or the host-window key on these read routes, including loopback, and reject agent credentials explicitly.

2. **Must-fix — the native font consent dialog is bypassable.** The remote session capability still grants [`allow-local-fonts`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/app/src-tauri/capabilities/session.json:7), and [`local_fonts`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/app/src-tauri/src/main.rs:835) returns installed font bytes without a dialog. The same page can then call `/fonts/lend`; the hub has no proof that [`lend_font`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/app/src-tauri/src/main.rs:842) was used. Remove raw, no-dialog font access from remotely served session pages. Keep local-only rendering behind a separate trusted boundary, and make lending a native operation that authorizes the transfer itself. The current consent claim in [SPEC.md](/Users/cheyrasmussen/jamsesh-p6/jamsesh/SPEC.md:1637) is false.

3. **Must-fix — another page on the same hostname can inject input into a proxied build.** [`devdrive.ts`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/devdrive.ts:9) checks hostnames but ignores scheme and port. Any page at another `localhost` port can frame the dev proxy and send `{jamDrive: ...}`; [the listener](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/devdrive.ts:37) accepts it without consulting the hub’s driver state. Bind messages to the exact authorized parent origin and a frame-specific capability issued by JamSesh.

4. **Must-fix — an arbitrary recording ID reaches a file output path.** [`recordSend`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/hub.ts:517) accepts an ID absent from `noteOwners`—the tests even send `"rec-x"` without a recording. It passes that ID into [`cropFor`’s `sips --out` path](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/hub.ts:500). For example, `crop-../../../target-0.png` resolves outside `uploadsDir`. Require a server-issued recording ID owned by the caller; construct crop filenames from a separate safe server-generated token and check path containment.

5. **Must-fix — callers can replace another device’s recording.** The HTTP route trusts the supplied [`deviceId`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/http.ts:820). [`recordStart`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/hub.ts:419) then ends any recording under that ID without checking its owner. A paired person who knows a victim’s device ID can interrupt their recording and release its screen lock by starting an ordinary recording. Bind the device ID to the authenticated window and check ownership before replacement.

6. **Must-fix — recording locks can be released while a recording is active, or after someone else takes the screen.** [`recordStart`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/hub.ts:409) acquires/checks the lock *before* ending a prior recording on the same device; that end can unlock the screen under the new recording. Later, [`recordEnd`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/hub.ts:456) unlocks solely from `tookLock`, without checking that this is still the lock it acquired. End the old recording first, then acquire the new lock; retain and compare a lock generation before releasing it. The existing replacement test checks only the final unlocked state.

7. **Must-fix — two sends can issue duplicate directives.** [`sentRecs`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/hub.ts:519) is checked before the asynchronous crop, then populated only after annotations, directives, and the brain event are written. Concurrent sends of a recording with a picture can both pass the check. Reserve an in-flight promise or durable send state before the first await, and test concurrent requests.

8. **Must-fix — Mac capture can select a different app’s window.** The helper matches window owners using [substring containment](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/native/jamsesh-live.swift:58) and chooses the largest match in [`findWindow`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/native/jamsesh-live.swift:104). A short or overlapping name can stream and receive CGEvents in the wrong process. Select an explicit window ID and verify its exact process identity throughout capture and input; stop when it disappears.

9. **Must-fix — CSP handling is inconsistent.** The proxy inserts its script [before the page’s head contents](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/devdrive.ts:53), so a meta CSP later in that head cannot protect against it. Conversely, [`allowDriveScript`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/devdrive.ts:62) adds a hash to `script-src` or `default-src` but misses `script-src-elem`, so those pages block driving. Handle both header and meta policies explicitly, or leave pages whose policy cannot safely permit the script undriven.

10. **Must-fix — the open-font size cap is applied after allocation.** [`download`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/fonts.ts:309) calls `arrayBuffer()` before checking its 24 MB face cap. A large or misbehaving response can exhaust hub memory despite the documented cap. Check `Content-Length` and stream with an enforced byte limit; bound catalogue and stylesheet reads too.

11. **Must-fix — an interrupted idb call can report input as delivered.** The gRPC client initializes [`status = "0"`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/idb.ts:233) and calls `finish()` on transport [close](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/idb.ts:269), even without trailers or a response. A companion crash during a tap or typing can be reported as success. Require a valid HTTP response and terminal gRPC status; report premature close as an unknown outcome.

12. **Must-fix — captured trackpad keys leak from other UI fields to the big screen.** [`DriveSurface`’s window capture listener](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/DriveSurface.tsx:92) forwards keys whenever its `captured` flag remains set. In fallback mode, clicking a different input does not clear that flag, so typing there is prevented and sent to the build or native app. Release capture on blur and require the trackpad to own keyboard focus before forwarding.

## Design and smaller issues

- **Should-fix:** The documented 120-event limit is per person, but [`driveFrom`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/http.ts:364) counts per WebSocket. Multiple sockets bypass it. Count after authentication by person or paired device.
- **Should-fix:** [`GET /drive/online`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/http.ts:637) is open to agents because `HUMAN_ONLY` is checked only for non-GET methods. Make this route people-only, as already identified in the brief.
- **Should-fix:** [`loadFonts`](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/roomFonts.ts:47) marks an entire family loaded when any one face succeeds. A failed bold or italic face is never retried. Track successful face indexes.
- **Design:** Delete the global [`recordControl` singleton](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/annotate.tsx:739). It can retain a callback from an unmounted `RecordPrompt`; a scoped controller or context would give `RecordHere` the active recorder.
