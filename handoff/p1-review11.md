## Must-fix

1. **Inbox messages can disappear in a busy room.** [session.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:695) selects the newest 50 messages *before* filtering for the recipient. If an agent’s unread message is followed by 50 messages to others, `jam_inbox` and `jam_wait` cannot find it. Filter by recipient in the store query before applying the limit, and page forward from the read mark. Add a test with more than 50 unrelated messages.

2. **A partially loaded font family can never finish loading.** [canvasJoin.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/canvasJoin.ts:207) retries only families still returned by `text.missingFonts`. Loading the first file can remove a family from that list even when the Mac reported another file as `incomplete`. `FontTries.partial` keeps the warning visible but is never included in the next request. Retry the union of missing and partial families; settle only after a complete response and successful loads. The [partial-family test](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/test/canvas-join.test.ts:122) checks the warning, not a retry after the first face loads.

3. **The parity exchange guard still accepts unrelated traffic.** [session.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:650) accepts an outgoing message to counterpart B and an incoming one from counterpart C as a completed exchange. [sendMessage](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:790) also inherits the last linked message between two agents without a time or reply boundary, so later unrelated conversation can acquire an old directive ID. Require a two-way exchange with the same counterpart. For plain replies, use an explicit `directiveId` or a reply reference rather than an unlimited “last linked” lookup; test both cases.

4. **Any agent can answer another agent’s question, and busy-room questions become unanswerable.** [session.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:836) looks up an `askId` in only the latest 400 messages and never checks that the answering agent is the question’s addressee. A third agent with the ID can supply the answer; after 400 newer messages the intended agent gets “No question.” Query the ask by ID without that window, require `q.data.to === fromId`, and reject a second answer. Test unauthorized and delayed answers.

5. **The bundled Mac recovery claim remains unverified.** The [watchdog tests](/Users/cheyrasmussen/jamsesh-p1/jamsesh/app/src-tauri/src/watchdog.rs:224) exercise timing and PID selection, not a hung WebKit page or hub restart in the installed app. Before shipping Phase 1’s automatic recovery claim, run and record a bundled Mac smoke test that hangs a page, restarts the hub, and confirms the window and canvas recover.

## Design and test concerns

- [relayDown](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/http.ts:51) closes on `send() === 0`. Bun also returns `0` for a **successfully sent empty message**, so a legal empty server message disconnects the canvas. Handle empty payloads separately and retain the buffered-byte check. The current [downstream test](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/test/relay-limits.test.ts:108) uses a nonempty fake payload. [Bun’s WebSocket documentation](https://bun.com/docs/runtime/http/websockets) confirms the return-value behavior.
- The [post-open relay](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/relay.ts:90) has byte accounting but no frame-count cap; many tiny frames can create a large pending array. The [“empty frames” test](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/test/relay-limits.test.ts:181) can stop on a large frame before reaching its empty-frame branch. Add an explicit count cap and make that test assert empty frames were actually sent.
- [RoomFeed](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/ui.tsx:395) retains, sorts, and renders every event seen by a long-lived window. Bound or virtualize it. Replace the [historyCursor microtest](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/test/feed-history.test.ts:10) with a feed test that exercises paging and scroll position.
- [Hub.shutdown](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/hub.ts:163) does not await canvas helper reaping. Parity recipients are still chosen by platform alone at [brain.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/brain/brain.ts:934); product identity remains the documented data-model decision.
- [SPEC.md](/Users/cheyrasmussen/jamsesh-p1/jamsesh/SPEC.md:1154) claims a host relay is available for WebRTC when needed, while [rtc.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/rtc.ts:33) defaults to STUN and I found no hub TURN configuration route. Correct the claim or provide that relay.

The font and exchange fixes remain incomplete as described above. I did not run tests: this was a read-only review, and the test suites create files and processes.
