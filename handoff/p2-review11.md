The launcher download, Claude settings edit, Codex config edit, and remaining downloads can still fail under `set -e` ([lines 422–578](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:422)). Keep the rollback data until the whole install succeeds; stage downloads first, and restore the MCP entry and host-specific files on every later failure. 2. **A stale HTTP response can switch the UI back to the previous room.** [hub.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/web/src/shared/hub.ts:280) adopts every completed `/state` request. If a fallback request to room A is in flight when the relay changes and the socket delivers room B’s state, A’s late response replaces B’s state. Later B socket patches then apply to A’s snapshot. The HTTP test covers sequential adoption only. Tag the request with a connection or state generation and discard its response after a newer socket state or reconnect; test the deferred-response order.

3. **Rollback can report success after a restore fails.** In [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:306), `restore_files` is called through `||`. Bash suppresses `errexit` inside that function; an early copy or move can fail while a later iteration succeeds, making the function return success. Both failure branches then delete the backup, and can claim the earlier setup was restored. Track each file’s result, retain backups when any restore fails, and report the affected paths. I confirmed this Bash return behavior with a shell check.
