## Must-fix

1. **Attached text can still induce agent work.** [brain.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brain/brain.ts:1540) treats any occurrence of `send` as permission to offer `create_directive`; execution repeats the same check at line 1080. I checked the predicate: “Summarize the file; **do not send** anything to an agent” passes. A malicious attachment can therefore steer the model toward a tool the person explicitly ruled out. Require affirmative, scoped intent for each action, and test negated and quoted requests.

2. **Opposite decisions are silently deduplicated.** [similarity.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/similarity.ts:28) counts negations globally and compares sets of specifics. A read-only probe confirmed `restates("Use option A, not option B", "Use option B, not option A", 0.55) === true`. [board.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/board.ts:171) can discard the second proposal; curation can merge it into the first fact. Compare which option each negation applies to, or conservatively send multi-option corrections to triage.

3. **A busy session permanently skips curation events.** [brain.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brain/brain.ts:1333) requests 400 events after the cursor, then advances to `lastId`. [store.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/store.ts:285) returns the *newest* 400. With 401 or more queued events, the older ones are never curated. Page from the oldest unprocessed ID and advance only through the batch actually processed.

4. **A proposal can default to replacing a fact from another scope.** [board.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/board.ts:176) searches all active facts for a conflict without checking kind or workstream. “Header uses 64px spacing” in Desktop and “Header uses 48px spacing” in Mobile score 0.75 similarity and become a Replace card; accepting its default retires the Desktop fact. Apply scope and kind checks to conflict selection, then test cross-workstream differences.

5. **Retiring a session’s own last fact can resurrect it.** [carryover.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:77) recognizes retirement only for *carried* items. At line 119, an empty snapshot after retiring a locally created fact is refused, leaving the previous `context.json` intact for the next session to seed. Track retirement of any settled item and write the resulting empty snapshot. The new regression test covers only a carried fact.

6. **The context writer can produce a file its reader rejects.** [carryover.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:35) caps `goal` at 2,000 characters and `brief` at 40,000 on read, while `snapshotContext` writes them without those bounds or a schema check. The digest’s [goal schema](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brain/brain.ts:1796) has no length limit. One oversized result makes the entire next session’s context unreadable. Validate and bound the snapshot before replacing the existing file.

7. **The `activeAt` guard is racy across hub processes.** [carryover.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:120) reads the current file, then writes and renames without a lock. Two sessions can both pass the check; the older one can rename last and overwrite newer context. Lock the project context across the read, comparison, and rename, then test interleaved writers.

8. **A Retire card can retire an unrelated fact.** [board.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/board.ts:381) accepts a caller supplied `factId` ahead of the card’s cited `conflictsWith`; the [HTTP route](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/http.ts:702) and spoken tool pass it through. A Retire card evidenced for fact A can thus mark fact B resolved. Reject an override on Retire cards and require the cited fact ID.

## Design concerns and nits

- The built-in PDF reader still scans every stream rather than traversing pages. [pdfworker.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/pdfworker.ts:28) extracted “Not on any page” from an unreferenced stream in a read-only probe. That is a **should-fix** to the “drawn text only” claim: use page-referenced content or return `needsWording` when reliable extraction is unavailable.
- [brief.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brief.ts:80) ignores the carried glossary when building the new session’s brief, although `glossaryOf` supplies it elsewhere. Use `glossaryOf(s)` here. **Should-fix.**
- Delete the unused `lastId` parameter and `void lastId` in `workstreamBriefs` ([brain.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brain/brain.ts:1409)). [STATUS.md](/Users/cheyrasmussen/jamsesh-p4/jamsesh/STATUS.md:43) still says document proposals use a stub until the Tasks board lands.

The second review’s fixes are present for `/say` identity, overheard questions, cited retirement, carried-item retirement, own-fact seeding, `needsWording` merge, curation retry, target revalidation, and worker isolation. The file gate, similarity check, carry-over, and PDF extraction still fail under the cases above.

**Verification limits:** I ran read-only predicate probes and inspected the routes, store, tests, and SPEC at the requested commit. I did not run the test suites because they create files and this review is read-only. I could not verify a real gateway call with an image or PDF, or PDF extraction from the bundled Mac app; [STATUS.md](/Users/cheyrasmussen/jamsesh-p4/jamsesh/STATUS.md:40) also marks the real gateway path untested. Those paths need end-to-end verification before this feature ships.
