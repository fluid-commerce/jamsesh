## Production findings

1. **Must fix — a host-ended share restarts itself.** [http.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/http.ts:600) ends the share without sending `share-ended` to its publisher. The capture keeps running; after ten seconds [rtc.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/rtc.ts:411) treats the absent live record as a connection loss and registers it again. [startShare](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:879) accepts the ended ID, and the HTTP handler puts it back on screen. A missed end message during disconnection has the same result. Notify the publisher on every hub-initiated end, and make re-registration distinguish connection recovery from an intentional end. Test host DELETE through the ten-second interval.

2. **Must fix — canvas recovery can remain reported as failed.** A failed resync sets `status: "failed"` in [canvas.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/canvas/canvas.ts:523). A later successful [resync](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/canvas/canvas.ts:508) never restores live status or advances the canvas generation. If the watchdog subsequently sees a healthy server and live peers, it does nothing, leaving the failure state in place. Announce the verified links after successful resync and test failure followed by success.

3. **Must fix — relevant room decisions can be lost permanently.** [roomDecisions](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:705) gathers decisions and returns the newest ten. [onPrompt](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/hub.ts:462) then advances `decisionsSeen` to the newest delivered ID. If eleven relevant decisions arrive between prompts, the oldest is skipped forever. Deliver the oldest unseen relevant page first and advance the mark only through that page. The new test covers many *irrelevant* decisions, not eleven relevant ones.

4. **Must fix — shipped news can still produce an unsupported directive.** The narrower shipped pass and “check before building” wording address much of the earlier finding. But [coordinate_parity](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/brain/brain.ts:919) checks only that `seen` is nonempty. It will accept an invented visible feature for a shipped note about invisible work and create `coordinate` inbox directives. Require the claimed visible behavior to be grounded in the shipper’s update before creating directives; test an invisible update with a fabricated `seen` value.

## Design concerns

- **Should fix — distinct shipments suppress one another.** [brain.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/brain/brain.ts:888) applies a ten-minute cooldown to an entire agent and branch; [the open-directive check](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/brain/brain.ts:909) likewise ignores which feature a directive covers. Two different features shipped close together can leave the second without a parity check. Deduplicate by feature and target.
- **Should fix — canvas polling is not single-flight after a timeout.** [JoinWatch](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/canvasJoin.ts:47) clears `busy` when its timeout wins, although the original `collab.peers` call may still be pending. Subsequent polls can stack unresolved calls. Cancel the underlying call or keep that canvas instance from issuing more reads until it is replaced.
- **Should fix — a transient font-load error becomes permanent for that canvas.** [loadLocalFonts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/canvasJoin.ts:117) marks every missing family as tried before `local_fonts` succeeds and swallows command failures. Retry families whose load did not complete.
