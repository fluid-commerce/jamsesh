## Must-fix

1. **The relay is unbounded after the canvas socket opens.** [http.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/http.ts:321) applies the 1,000-frame and 8 MB caps only before `OPEN`. Afterward, every client frame goes straight to `up.send()` without checking its buffered bytes; frames coming back ignore downstream send backpressure too ([http.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/http.ts:375)). A connected but stalled peer can therefore queue data beyond the advertised cap. Bound both directions after opening, close with 1013 when a peer cannot drain, and test an upstream that completes the handshake but stops reading.

2. **Child shutdown is still not bounded.** The parent-death watcher sends TERM and then waits indefinitely if a canvas or MCP child ignores it ([children.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/children.ts:16)). `Canvas.stop()` and `FigcraftMcp.close()` only send TERM; neither reaps or escalates ([canvas.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/canvas/canvas.ts:133), [figcraft-mcp.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/canvas/figcraft-mcp.ts:142)). The `figcraft-server key` child is spawned without a parent watcher at all, so it can outlive a hub killed during its ten-second wait ([canvas.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/canvas/canvas.ts:197)). Give the watcher its own TERM grace and KILL fallback; make Stop reap wrapped children; wrap and track the key child. Test TERM-resistant children under both Stop and hub death.

3. **The font handoff discards installed faces.** The Mac returns one entry *per font file* for a family ([fonts.rs](/Users/cheyrasmussen/jamsesh-p1/jamsesh/app/src-tauri/src/fonts.rs:89)), but the page reduces them to one map entry and loads only the last file ([canvasJoin.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/canvasJoin.ts:216)). Regular and Bold in separate files, for example, cannot both reach the canvas. The Mac also silently truncates requests to 24 families or 96 MB, while the page marks every omitted family permanently unavailable ([fonts.rs](/Users/cheyrasmussen/jamsesh-p1/jamsesh/app/src-tauri/src/fonts.rs:78), [canvasJoin.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/web/src/shared/canvasJoin.ts:219)). Load every returned file and distinguish “absent” from “not attempted”; batch further requests. Test a family with two files and a capped response.

4. **A parity directive can close without the required comparison.** The new directive correctly says to agree through `jam_message`, but `jam_update` with `kind: "shipped"` and that directive’s ID immediately marks it done ([mcp.ts](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/mcp.ts:422)). [setDirectiveFor](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/session.ts:642) has no parity-specific check. An agent reporting its own shipment can close its check before the other agent replies. Keep coordinate directives open on `jam_update`; require an explicit completion after a recorded exchange with the named counterpart.

## Design concerns

The four must-fixes in review 8 have corresponding changes: the host MCP child is tracked before initialization and retains stdin through the wrapper; the relay now caps pre-open traffic and times out; the cited fix descriptions are filtered through the shipped path; and the inbox reminder calls for comparison first. The new findings above limit the child and relay claims.

The disputed recipient-scoping issue remains a **should-fix**. [parityTools](/Users/cheyrasmussen/jamsesh-p1/jamsesh/hub/src/brain/brain.ts:934) sends checks to every online app agent on the selected platform. Repo and platform do not reliably identify the same product, so selecting a recipient needs a product identity in the agent record. The directive is now a conditional check rather than an immediate build task, which keeps this from blocking Phase 1. The shipper’s `seen` text is used verbatim, and the tool no longer accepts a feature label from the model.
