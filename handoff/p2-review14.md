## Must-fix

1. **Stale-lock recovery can steal a live setup’s lock.** [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:308) reads a dead PID, then moves `setup.lock` without checking that it is still the directory it read. Two waiting runs can both read the stale PID; one moves the stale lock and acquires a new one, then the other moves that *new, live* lock. Both can now change and roll back the same files. The unconditional `rm -rf` at line 306 can also remove the other run’s lock. Use an OS advisory lock held for the full transaction, including recovery and rollback.

2. **Rollback can overwrite an unrelated file or follow a symlink into an instruction file.** [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:359) copies each backup to the predictable path `$real.restore`. An existing file there is overwritten and then renamed away; an existing symlink is followed by `cp -p`. For a tracked path such as `~/.claude/settings.json`, a `settings.json.restore` symlink can make rollback write to `CLAUDE.md`, violating the instruction-file constraint. Create an exclusive private temporary file beside each target and rename it into place. Test a pre-existing `.restore` file and symlink.

3. **The MCP rollback still has an argv secret path.** [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:466) classifies a saved HTTP URL as safe for `add-json` unless it contains `@`, `?`, or `#`. A credential in a path, such as `https://example.test/mcp/secret_value`, selects `argv`—I ran the classifier with that value and it returned `argv`—and lines 474 and 371 pass the URL in a process argument. Restore the complete saved entry through the private config-file path, or require an explicit allowlist that cannot carry credentials.
