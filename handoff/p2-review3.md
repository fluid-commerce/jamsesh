## Production blockers

1. **A later chat can take over an offline chat’s agent record.** In [session.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/session.ts:459), the last resume fallback accepts a different `chatId` after the old agent has been offline long enough. It also accepts a different machine, then replaces the record’s machine and chat ID. The new chat inherits that agent’s identity and work. This contradicts the same-machine, same-chat contract in [SPEC.md](/Users/cheyrasmussen/jamsesh-p2/jamsesh/SPEC.md:334). Restrict this fallback to legacy records without a chat ID; require an exact chat and machine match for named chats. Test a second chat in the same folder after 20 minutes and a chat on another machine.

2. **The inbox can permanently skip messages.** [session.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/session.ts:928) takes the newest 50 *global* message events before filtering for the recipient. Fifty newer messages to other agents can hide an unread direct message; more than 50 messages to one agent lose the older ones when `msgRead` advances. Hooks, `jam_inbox`, and `jam_wait` share this inbox. Filter by recipient before limiting, or page forward from the unread cursor. Test both cases.

3. **The setup script interpolates a request header into executable shell.** [http.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/http.ts:846) builds the setup origin from `x-forwarded-host`; `knownHost` checks `Host`, not that forwarded value. [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:274) puts the result inside `HUB="..."` without shell escaping. A crafted forwarded value can execute shell syntax when the generated script runs. Validate the origin against an allowed host and shell-quote every value embedded in the script. Add a hostile-header test that runs the generated script in a disposable home.

4. **Installation can expose existing secrets.** [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:407) rewrites `~/.claude/settings.json` through a new temporary file after resetting the umask to `022`. A formerly `0600` settings file can become `0644`; its unrelated contents may include secrets. The script also creates `~/.jamsesh` before setting umask `077`, and redirection does not tighten existing credential files. Preserve the settings file’s permissions, make the directory `0700`, and atomically replace credential files with mode `0600`. Test reinstalls over permissive files and a private existing settings file.

5. **Revocation does not stop an already open wait from returning room content.** [http.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/http.ts:179) checks the credential when a request starts. The listener in [hub.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/hub.ts:632) and `jam_wait` in [mcp.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/mcp.ts:495) recheck agent membership, but not credential revocation. Revoke the credential during a wait and then send a directive: the old request can return it. Wake or cancel waits on revocation and recheck the credential immediately before handover. Test both wait paths.

6. **Terminal directive states can be reopened or remain actionable.** [session.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/session.ts:901) protects `cancelled` from a late `jam_ack`, but not `done`; a late `acked` changes a completed directive back to open. Conversely, the whole-directive status route in [http.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/http.ts:546) changes only `status`, leaving per-target `progress` open, which the inbox and tiles prefer. Make terminal transitions monotonic and update per-target progress when a whole directive ends. Test out-of-order acknowledgements and cancellation through the HTTP route.

7. **Some offered reassignments have no button.** [ui.tsx](/Users/cheyrasmussen/jamsesh-p2/jamsesh/web/src/shared/ui.tsx:769) renders only the first three open tasks, or one in a compact tile, and places `Reassign` only on those rows. An offer on a later task tells the room to use a control it cannot see. Put offered tasks first or expose the full task list. Test four open tasks with an offer on the fourth.

8. **Reinstall can corrupt Codex’s global TOML.** [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:434) removes a JamSesh section only until the next `[` character, including one inside a value such as an IPv6 URL. It leaves a fragment of the old section before appending the new one. Match actual section headers at line starts or use a TOML parser; test an IPv6 URL and bracketed comment.

## Design concerns and tests

- **Should fix:** [session.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/session.ts:741) patches per-target nudge and offer maps from the same stale directive snapshot. When several targets age in one tick, later patches overwrite earlier entries and notices can repeat. Read the updated directive between targets or accumulate one patch, then test simultaneous aging.
- **Should fix:** [http.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/http.ts:539) accepts an observer-only product directive before [session.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/session.ts:837) strips its targets. The request reports success although nobody receives it. Reject an empty eligible target set.
- **Should fix:** The Claude hook commands in [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:399) do not quote the hook path. A home path containing spaces breaks delivery. Quote it as a shell argument.
