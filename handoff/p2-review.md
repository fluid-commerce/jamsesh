## Production findings

1. **Must fix — paired devices can take over another chat’s MCP session.** [session.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/session.ts:182) exposes each agent’s `chatId` in `/api/state`. For Codex, [mcp.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/mcp.ts:398) makes that ID `mcp:<session UUID>`. At [mcp.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/mcp.ts:293), a request with that UUID reuses the existing agent context without checking the authenticated device. A different paired device can therefore make tool calls as the victim. Keep transport IDs out of room state and bind every MCP session request to the device that created it.

2. **Must fix — hook routes trust caller-supplied identity.** [hub.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/hub.ts:436) accepts any `agentId`, or a `session_id` matching any Claude agent, while discarding the IP and device arguments. [http.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/http.ts:556) permits agent credentials on these routes, and loopback needs no credential. An unjoined or foreign caller can drain another agent’s inbox through `/tool` or `/listen`; `/prompt` also records text as that agent’s *person* and sends it to the brain. Check credential kind and bind the hook chat to its issuing device before reading or changing anything. Remove the unrestricted `agentId` fallback.

3. **Must fix — the installer turns a person’s name into shell code.** [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:185) reads a room-controlled name, writes it unescaped into a quoted assignment in `client.env` at line 193, and the hook sources that file at line 14. A name containing shell substitution executes on the person’s Mac when a hook runs. Serialize shell values safely, or read a data format without sourcing it. The script also passes the bearer token in `curl -H` and `claude mcp add --header` arguments (lines 227–229), exposing it to process listings; move those credentials out of argv.

4. **Must fix — block cleanup can alter instructions beyond JamSesh’s block.** [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:99) accepts markers anywhere, removes indentation after the end marker at line 104, and collapses preceding blank lines at line 107. Its rename at line 117 replaces a symlink with a regular file. That breaks the documented shared `CLAUDE.md`/`AGENTS.md` symlink setup when an old block is present. Match only the exact historical block at line boundaries, preserve surrounding bytes, and update a symlink’s target without replacing the link.

5. **Must fix — delivery is at most once, with silent loss.** [hub.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/hub.ts:485) marks inbox items delivered before the hook response reaches Claude. The hook gives `/prompt`, `/tool`, and `/stop` only two seconds ([install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:64)); a timeout or lost response leaves the item consumed. The listener has the same gap. Use delivery IDs and an acknowledgement or replay protocol so a failed response can be retried.

6. **Must fix — Remove with purge deletes other authors’ content and leaves some agent content.** [store.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/store.ts:237) deletes every event *addressed to* the agent, including another agent’s direct message, and person-authored prompts tagged with its ID. [session.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/session.ts:522) leaves that agent’s stored long documents and artifacts. Define the purge boundary explicitly, delete only content covered by the confirmation, and include its document records where promised. Also reject a removed chat’s `jam_join` until a person reconnects it; the current join path has no removal check.

7. **Must fix — Reassign does not work from the tile.** [ui.tsx](/Users/cheyrasmussen/jamsesh-p2/jamsesh/web/src/shared/ui.tsx:738) calls `api("/api/directives/…")`, while [hub.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/web/src/shared/hub.ts:415) adds `/api` itself. The click reaches `/api/api/directives/…` and its error is swallowed. Pass `/directives/…` and show a failed request. The test calls `Session.reassignDirective` directly, so it cannot catch this.

8. **Must fix — reassignment can cancel agents who are still working.** The offer is stored once per directive, so every target’s tile gets the button. [session.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/session.ts:745) then cancels *all* unfinished targets, even if only one was stale. Track the offer and reassignment by target agent, and pass that target from the clicked tile.

9. **Must fix — task aging does not measure progress on that task.** [session.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/session.ts:728) treats any recent update by the agent as progress on every directive and uses a shared `deliveredAt`/`updatedAt` for targets. Work on an unrelated task can indefinitely postpone a nudge; another target’s activity can reset the clock. An offer also remains visible after the stalled agent reports back. Track per-target, per-directive progress times and clear an offer when that target resumes.

10. **Must fix — normal completion and joining produce misleading tiles.** A `jam_update(done)` sets `Done: …`, then its own `PostToolUse` hook immediately changes the activity to “Working” ([hub.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/hub.ts:527)). Separately, the prescribed first `jam_claim` after `jam_join` is announced as work “nobody asked for”: the connect prompt was ignored before the chat joined, so [session.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/session.ts:663) sees no prompt. Exempt the completing JamSesh tool from that status reset, and treat the initial authorized claim as asked-for work.

11. **Must fix — an observer becomes a worker on rejoin.** [mcp.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/mcp.ts:386) passes `role: "worker"` whenever `role` is omitted, overwriting the existing observer role despite the SPEC’s promise to preserve it. Preserve the stored role unless the caller explicitly changes it. Enforce observer restrictions at `jam_claim` too; it currently lets an observer take a workstream.

## Design, tests, and docs

The persistent `~/.jamsesh/chats/<session_id>` marker ([install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:27)) is never invalidated after Remove or a host switch. It skips the joined check and sends later full prompt bodies to the hub, contradicting the “send nothing for an unjoined chat” claim. Revalidate against the current host, or remove this cache.

The new tests cover scripted happy paths but miss authenticated cross-device requests, a response lost after inbox consumption, the real Reassign click, a multi-target directive, observer rejoin, `jam_update(done)` followed by `PostToolUse`, and symlinked instruction files. Those cases are needed before the Phase 2 claims are credible. SPEC and STATUS also still call the wake-up simulated although the review brief says an interactive Claude Code chat verified it.

I did not run the test suite: this review is read only, while these tests create databases and temporary files. I could not verify real Claude Code hook delivery or the reported interactive wake-up from this checkout.
