## Must fix

1. **An attachment can bypass the file gate through “Say to room.”** [hub.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/hub.ts:293) sends a message with words and `direct: false` to `brain.hear`. [brain.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brain/brain.ts:284) then builds overheard tools without the file flag, so screen and host tools remain available; its offline fallback can also change the stage at [brain.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brain/brain.ts:1170). For example, a room message with a file and “show us the join code” can change the screen without a card being accepted. Carry the attachment flag through overheard routing and its fallback, and enforce the file allowlist at execution.

2. **A passive restatement can resurrect a fact another session retired.** [curation.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/brain/curation.ts:157) advances `updatedAt` when it merely adds a source to an active fact. The older session still sees that fact as active. If another session retires it, the older session’s later restatement is written as a newer active row by [carryover.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:234). No person reaccepted it. The same timestamp scheme also drops a carried item changed in its seed millisecond (`updatedAt > carriedFrom.at`) and permits equal-time stale replays (`<=`). Separate semantic changes from source bookkeeping and use an ordered revision or conflict record rather than millisecond timestamps to decide whether a retirement may be reversed.

3. **Seeding drops accepted facts that share wording.** [carryover.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:292) deduplicates by normalized text alone. Two accepted rows with the same text in different workstreams or of different kinds survive in SQLite, but only the first enters the next session. Seed by project ID; if duplicate suppression is needed, include kind, workstream, and scope. The large-set test uses unique wording throughout, so it cannot catch this.

4. **The JSON export can publish a transaction that never commits.** [carryover.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:200) renames `context.json` inside the SQLite transaction, before commit. A process death or commit failure after the rename leaves Phase 7’s wiki with facts absent from the database; subsequent legacy import can also take that export as settled context if the DB is missing. Publish only after a successful commit, with serialized/version-checked export so concurrent writers cannot publish out of order; rebuild the export from the DB during recovery.

5. **Corrupt-DB recovery recreates the lock takeover race.** [carryover.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:214) closes the connection and renames `context.db`, WAL, and SHM without a recovery lock or identity recheck. Two processes that both observe corruption can interleave: one quarantines the bad file and writes a new DB, then the other quarantines that new DB. Fail closed on corruption, or serialize recovery and recheck that the file being moved is the one diagnosed. Test competing recovery processes.

6. **A veto’s provenance is still erased after repeated overrules.** [board.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/board.ts:450) keeps only the last 12 `vetoes`, while replacing the single `overruled` summary. The thirteenth overrule deletes the first veto’s reason, person, and cited lines, contrary to the stated “for good” history. Keep the full veto history in the store, with any display limit applied only when reading it.

7. **Attachment credentials can enter URLs, and revocation cannot invalidate cached reads.** [http.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/http.ts:89) accepts `?token=` on attachment GET/HEAD; the new test explicitly uses it. That exposes a credential to URL histories and logs. The response at [http.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/http.ts:593) is also privately cacheable for a year and `immutable`, so a browser can serve an already fetched file after pairing is revoked without checking the hub. Accept headers or cookies for this route and require revalidation or `no-store`.

## Design and tests

The Round 5 changes are present on their intended paths: direct file passes propose cards, SQLite writes changed rows under `BEGIN IMMEDIATE`, vetoed asks get a `renews` card, accepted-set caps are gone, and loopback attachment reads check supplied credentials. The direct-pass file test at [p4-round5.test.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/test/p4-round5.test.ts:58) does not exercise `direct: false`; the overlap tests use distinct texts and separated timestamps; the writer tests do not race corrupt-DB recovery or export against commit failure.

[carryover.ts](/Users/cheyrasmussen/jamsesh-p4/jamsesh/hub/src/carryover.ts:95) silently omits a fact with an invalid status despite the documented whole-file validation. Validate that status. Delete the unused `activeAt` alias, which always equals `updatedAt` and no longer guards ownership.
