## Must-fix before shipping

1. **The legacy prompt routes bypass recording ownership.** [http.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/http.ts:894) accepts any paired person’s `deviceId` on `/prompt-window/start` and `/prompt-window`; it lacks the `ownDevice` check used by the new Record routes. The start call replaces that device’s prompt window, and the stop call reaches [hub.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/hub.ts:371), which ends its active Phase 6 recording and may release its screen lock. Device IDs are visible in room state. Apply the same authenticated device check to both legacy routes and test a cross-person request.

2. **A delayed Stop can end a newer recording.** [hub.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/hub.ts:492) captures the current recording, waits up to seven seconds for transcription, then `recordEnd(deviceId)` at line 496 deletes whichever recording is current. A new Start during that wait is lost. End only the captured recording by identity, and test overlapping Stop and Start calls. `promptWindow` has the same pattern.

3. **A rejected Start destroys the existing recording.** [hub.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/hub.ts:427) ends the previous recording before checking whether the requested screen exists or whether the person may drive it. A 404 or 409 therefore stops a valid recording. Validate the replacement first; add a failed-replacement regression test.

4. **Mac drags can remain pressed.** [liveapp.tsx](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/liveapp.tsx:162) discards a driver’s press on `leave`; [DriveLayer.tsx](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/host/DriveLayer.tsx:132) can subsequently route `up` back to that tile, where it is ignored because the press is gone. A local `pointercancel` also clears the press without sending `up` ([liveapp.tsx](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/liveapp.tsx:190)). Independent HTTP requests for down, move and up can also arrive out of order. Send a terminal up on cancellation or loss of capture, retain drag state until release, and serialize Mac input for each tile.

5. **Concurrent open-font downloads can exceed the 96 MB room cap.** [fonts.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/fonts.ts:351) calculates remaining space from fonts already held, then awaits the download; separate families commit later at line 375. A scan starts three families concurrently, so each can spend the same remaining allowance. Reserve space for in-flight reads or enforce the aggregate cap at commit, with a concurrent-download test.

6. **Build driving loses its key after a hub restart.** [drivetiles.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/drivetiles.ts:8) caches the frame key for the page’s lifetime, while [devproxy.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/devproxy.ts:57) generates a new key for each hub instance. The room page reconnects without necessarily reloading, so its events carry the old key and are silently ignored. On reconnect, refresh the key and reload proxied frames so their injected script has the matching hash.

## Design concerns and smaller fixes

- **Mac capture runs without viewers.** [liveapps.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/liveapps.ts:209) launches the 30 fps helper immediately; unsubscribe only removes a callback at line 381. Tie helper capture to the first and last subscriber. The `subscribe` comment currently claims capture runs only while watched.
- **One paired person can exhaust font-lending tickets.** [fonts.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/hub/src/fonts.ts:497) permits 100 outstanding tickets globally, without a per-caller limit or a check that the family is wanted. Repeated requests can block other lenders. Limit or replace tickets per caller.
- **Delete the module-global Record controller.** [annotate.tsx](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/annotate.tsx:743) retains a callback after `RecordPrompt` unmounts. A scoped React context would give `RecordHere` the mounted recorder.
- **The trail documentation is inaccurate.** [SPEC.md](/Users/cheyrasmussen/jamsesh-p6/jamsesh/SPEC.md:1496) says hue follows distance travelled; [trailmodel.ts](/Users/cheyrasmussen/jamsesh-p6/jamsesh/web/src/shared/trailmodel.ts:91) calculates it from elapsed time. Align the code or the description.

The legacy prompt routes leave the device-ownership fix incomplete.
