## Must-fix

1. **Rollback can falsely report that the Claude MCP entry was restored.** [install-scripts.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:339) ignores failure from `claude mcp remove`. On a first install, if registration succeeds and a later setup step fails, a failed removal leaves the new entry installed. With no earlier entry to re-add, the script still deletes its backup and says the earlier connection was put back. Check removal and verify the resulting entry or absence before reporting restoration; retain the backup and report failure otherwise. Test this with a fake Claude CLI that accepts `add-json` and refuses `remove`.

2. **Overlapping HTTP fallbacks can put the UI back in an old room.** [hub.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/web/src/shared/hub.ts:283) does not order HTTP responses when state was initially `null`: both requests capture an undefined room and the same `stateGen`. I started requests for rooms A and B, completed B first, then A; the final state was **room A**. A delayed request can outlive a socket reconnect because closing the socket does not cancel the in-flight fetch. Give requests a monotonic generation tied to the connection, and discard answers superseded by a newer request or connection. Add the overlapping-response test; the current test covers only an HTTP answer following a socket state.
