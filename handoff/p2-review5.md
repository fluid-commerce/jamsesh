## Must fix before shipping

1. **A removed Codex chat can rejoin after its MCP session resets.** [mcp.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/mcp.ts:305) generates a new session ID after a reconnect or hub restart, and [jam_join](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/mcp.ts:404) uses it as the Codex chat ID. The new ID misses the removal record and the old agent record. That defeats the documented rejoin gate and strands the old chat’s workstreams and directives. Give Codex a stable chat handle across MCP initialization, and test removal and resume through a new MCP session.

2. **`jam_ask` can return room content after removal or credential revocation.** [mcp.ts](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/mcp.ts:519) awaits an answer without the post-wait agent and credential checks present in `jam_wait`. Removing or disconnecting the asker neither ends that wait nor prevents a later answer reaching its open response. Cancel outstanding asks on removal or revocation, then recheck authorization before returning. Test both events while an ask is pending.

3. **Prompt and tool hooks can exceed their installed timeout while replaying queued prompts.** [hook.sh generation](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:114) allows 3 seconds for the joined check, 4 for the main call, then up to two more joined checks and 4-second replays under a lock. That exceeds the [15-second installed timeout](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/install-scripts.ts:430). A slow host can repeatedly kill the hook before Claude receives its room context. Move replay out of the foreground hook or enforce one deadline for the entire invocation; test two slow replays.

4. **Older open tasks disappear from agent tiles.** Both the initial state and directive patches retain only the [newest 60 directives](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/session.ts:187). The [tile builds its task list from that state](/Users/cheyrasmussen/jamsesh-p2/jamsesh/web/src/shared/ui.tsx:705), so an older task offered for reassignment has no visible Reassign button once 60 newer directives exist. Include every open directive in the tile’s state, and test an offer beyond the current window.

5. **A blocked report becomes “Working,” then “Done.”** [PostToolUse](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/hub.ts:608) preserves a `Done:` update from JamSesh’s own tool, but changes a `jam_update(kind: "blocked")` or `question` from blocked to working. [Stop](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/hub.ts:682) then labels its final message `Done:` and sets it idle, even with unfinished work. Preserve blocked and question reports through their own hook and Stop; add a regression test for each.

## Design concerns and verification

[Unprompted-work detection](/Users/cheyrasmussen/jamsesh-p2/jamsesh/hub/src/session.ts:720) searches only the latest 60 prompts across the room. A busy room can push a recent prompt for this agent out of that window and falsely announce that nobody asked for its work. **Should fix:** query by agent and time without a room-wide count limit.

The eight Round 4 fixes are present in the pinned source: join-on-request instructions, observer and update claim guards, forward decision paging, narrow hook removal, private temp files, comment-aware TOML scanning, rejection of invalid named recipients, and the dev-server generation check. This confirms the code paths, not the full installed flow on two Macs.

I did not run tests: they write temporary files, and this review was explicitly report-only in a read-only workspace. The new tests do not cover the five failure paths above. The documented sibling `craftrules/AGENTS.md` was unavailable here. I would delete the production `onListen` wrapper and `findAgentByCwd` if no supported caller remains; neither participates in the reviewed paths.
