## Must fix before shipping

1. **Direct vault edits bypass the source and recovery rules.** [service.ts:911](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:911) logs edits only through `editPage`; there is no file watcher or scan for changes made in Obsidian. Those edits also leave `index.md` stale. In the narrower crash window, an accept can rename a page but fail to save `applied`; if an external editor then removes its `write:` property, [reconcile() at service.ts:750](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:750) treats the landed write as rolled back. Dismissal can then read its sources without logging or indexing that write. Track external revisions as edit sources and reconcile outstanding intents before incorporating them. If proof has already disappeared, keep the card unresolved for explicit recovery instead of silently rolling it back.

2. **An identical edit during the model call silently consumes sources.** [service.ts:654](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:654) compares output with the *current* page before checking the revision shown to the model. If a person changes page A to the model’s proposed text B while the call is pending, `propose()` drops the change; with no other changes, [line 601](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:601) marks its sources read. The promised stale card never appears. The stored `before` at line 665 is likewise the later page, not the model’s input. Pass the captured text and revision into `propose()`, check staleness before equality, and keep those sources pending or show a stale card. Build both diff sizes from the captured text.

3. **Shutdown still has an uncaptured tail.** [index.ts:103](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/index.ts:103) leaves the HTTP server running through `hub.shutdown()`. [hub.ts:227](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/hub.ts:227) captures the transcript once, then can wait 15 seconds for a flush queued behind a model call. A message arriving after that capture has no source when the process exits into a new session. Stop incoming activity before the final capture, or capture again after the flush wait and before exit. Test the actual shutdown path with a blocked model call and a late message. The stated five-second budget also cannot interrupt synchronous `captureFinal()` work.

4. **The graph has no edge bound.** The hub allows 1,500 pages of 40,000 characters and emits every valid link ([files.ts:334](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/files.ts:334)). [graph.ts:48](/Users/cheyrasmussen/jamsesh-p7/jamsesh/web/src/wiki/graph.ts:48) processes all edges before its node cap; [GraphCanvas.tsx:189](/Users/cheyrasmussen/jamsesh-p7/jamsesh/web/src/wiki/GraphCanvas.tsx:189) draws all of them each frame. A valid densely linked vault can contain over two million directed edges, overwhelming the route, layout, and browser. Bound or aggregate edges on the hub before serialization, and cover a dense legal vault in a browser performance check.

5. **Malformed numeric state can pass validation and skip work.** [files.ts:583](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/files.ts:583) accepts fractional and unsafe numbers for event cursors and source offsets. A corrupted large `reports` or `cursors` value skips future events; a `read` offset beyond a source’s length is clamped to its end and can mark that source ingested without reading its text ([service.ts:549](/Users/cheyrasmussen/jamsesh-p7/jamsesh/hub/src/wiki/service.ts:549)). Require nonnegative safe integers and reject offsets beyond the corresponding source length.
