## Must fix before shipping

1. **A delayed share can replace a newer person’s lock.** [brain.ts:313](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/brain/brain.ts:313) captures the stage and lock, then waits up to 45 seconds for the presenter. Its fallback at [brain.ts:331](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/brain/brain.ts:331) calls `setStage` with `override: true` and the old lock. If another person casts during that wait, the fallback replaces their screen and can restore the previous owner’s lock. The catch path can also put an ended share back up after `endShare` or `Brain.stop`. Before any fallback, check that the share is still live, the brain is running, and the screen still has the stage and lock the placement started with. Test a delayed presenter followed by another cast and by share end.

2. **One spoken “yes” can approve requests for multiple screens.** [brain.ts:133](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/brain/brain.ts:133) applies the same speech batch to every pending show request. [showVerdict at line 1500](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/brain/brain.ts:1500) accepts an owner’s bare yes within each request’s answer window. Two screens locked by the same person can therefore both be replaced by one answer. [releaseLock’s timestamp check](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/session.ts:1637) has the same ambiguity when two lock questions are open. Bind an answer to one request or screen; refuse an ambiguous bare answer. Test two simultaneous questions.

3. **An explicit stale screen target can still select a different display.** [findScreen at session.ts:1408](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/session.ts:1408) falls back to substring matching. With `screen-2` connected and named “Screen 2,” explicit stale ID `screen-20` matches it. The HTTP and brain `screenRef` checks then accept the wrong screen instead of rejecting the request. Resolve IDs exactly and names by exact normalized match, or reject ambiguous matches. Test overlapping stale IDs and names.

4. **Migration can verify a copy that lost committed WAL data.** [projects.ts:339](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/projects.ts:339) copies the legacy database and WAL as separate live files. A checkpoint between those copies can leave committed rows out of the scratch database. The check at [projects.ts:393](/Users/cheyrasmussen/jamsesh-p3/jamsesh/hub/src/projects.ts:393) compares that scratch database with its own `VACUUM` output, so both counts match and the incomplete migration is marked verified. Take a consistent SQLite backup or keep the source writer stopped throughout copying. Test a writer and checkpoint during migration.

5. **Display arrangement is outside the session transition turn.** [screens.rs:547](/Users/cheyrasmussen/jamsesh-p3/jamsesh/app/src-tauri/src/screens.rs:547) captures a hub origin, then [arrange at line 486](/Users/cheyrasmussen/jamsesh-p3/jamsesh/app/src-tauri/src/screens.rs:486) changes windows and posts screen configuration without checking that the same hub still owns them. Leave or a project switch can stop that hub and close its windows while the delayed arrangement reopens an old-origin window; reused ports can send its display map to the next hub. Menu and screen-save paths also call `arrange` outside `Turns`. Tie arrangement to a session generation, validate it before window changes and the hub post, and invalidate pending work on transitions.

6. **Two queued Reopen requests can restart after a failed save.** [Turns::quit at main.rs:149](/Users/cheyrasmussen/jamsesh-p3/jamsesh/app/src-tauri/src/main.rs:149) accepts both terminal turns. If the first `final_stop` reports a failed save, it has already removed the hub and allows the app to keep running. The second then sees `hub=None`, treats that as success at [main.rs:504](/Users/cheyrasmussen/jamsesh-p3/jamsesh/app/src-tauri/src/main.rs:504), and requests restart at [main.rs:1092](/Users/cheyrasmussen/jamsesh-p3/jamsesh/app/src-tauri/src/main.rs:1092). Coalesce or reject terminal requests queued behind another terminal turn; test two concurrent Reopen calls with a failing stop.
